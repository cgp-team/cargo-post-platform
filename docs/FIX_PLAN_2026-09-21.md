## 3. 待其他模型（W4-W5 其余，列位置不动代码）

### 3.1 后端状态机 CAS（P1）
- `audit` 无 CAS（并发一通过一拒绝互相覆盖）—— `DriverAppServiceImpl` 审计方法
- `disputeHandover` 可把 COMPLETED 覆盖回 EXCEPTION
- `confirmHandover` 内存幂等检查两司机并发重复通知
- `pickupConfirm` 的 `loadedCount` 无 CAS，连点超容（L836 附近）
- 长事务：`createSmartPlan` `@Transactional` 含算法 HTTP 调用；`reportLocation` 事务含微信订阅消息 HTTP

### 3.2 管理端表单校验缺失（P1，5 个核心表单）
- 司机表单、车辆表单、站点表单、线路表单、订单表单：`formRules` 仅覆盖 1-3 字段
- 缺：手机号正则 / 车牌正则 / 经纬度范围 / 起终点不同 / 时间交叉校验
- `el-radio` 用 `:label` 应为 `:value`（EP 新版选不中）
- 6 处危险操作无二次确认：归集入池 / 智能调度 / 拒绝承运 / 商品订单完成 / 标记争议 / 所有删除
- `transport` 全模块未用 `DictTag`，枚举硬编码；route 列表直显数字 ID 而非站点名

### 3.3 小程序其余（P1/P2）
- `notification.js:15-29` 状态 emoji map（POOLED📥 等）需改文字/icon 组件
- **全项目 0 处 `binderror`**：所有 `<image>` 加载失败无兜底（农村弱网破图），建议统一封装图片组件
- `depart` 只推货运订单（orderType=2），邮快件/客运不动；admin 与司机端 departure 双路径不一致
- 三端都要手动刷新才见新单（用户端 notification onShow 不 reload；管理端 order/notification 列表无轮询；司机端 workbench 无轮询）

### 3.4 算法其余（P1）
- `jobs` 字典无持久化/无上限/重启即丢（24h 幂等破裂 + 无 OOM 防护）
- `amap_provider` 单例 `httpx.Client` 非线程安全 + 无锁，`time.sleep` 限速阻塞线程池
- 边界缺失：Station 经纬度无范围（NaN/Inf 污染 cost 矩阵）；PlanOrder 客/货运自环未校验；`MAX_STATIONS` 代码 100 vs 消息 30 vs 契约 30 三方不一致

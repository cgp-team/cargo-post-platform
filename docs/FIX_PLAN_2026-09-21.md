### 1.5 `createSmartPlan` 长事务重构（`c980bbc9`，原评估「不盲改」项）

**问题**：`@Transactional` 包住全方法——CAS 抢占行锁 + DB 连接跨越最长 15s 算法 HTTP 调用；
并发派单在行锁上串行阻塞；算法抛 RuntimeException 时任务 FAILED 记录与补偿**随事务回滚丢失**
（与注释宣称的"任务终态落库"不符）。

**重构**（TransactionTemplate 四段编排，方法级 `@Transactional` 移除）：
1. 只读准备（订单池/窗口/场站车辆/骨架/规模预检）
2. 调算法（无事务、未抢占未建任务，异常零补偿）
3. 短事务：CAS 抢占 + 建任务（失败整事务回滚，无中间态）
4. 短事务：任务 SUCCESS + 方案/明细/估算原子落库；失败补偿
   `failDispatchTask` + `cleanupPartialPlan`（planLegs 是 REQUIRES_NEW 需清理）+ `releaseClaimedOrders`

**行为修正**：INFEASIBLE/FAILED 终态真正落库；崩溃安全（算法阶段崩溃无 ASSIGNED 滞留）；
并发派单不再互相阻塞（代价：后提交者得 `DISPATCH_POOL_EMPTY`）。
**验证**：静态核对（括号配对零差值 + 变量声明/调用点 grep 复核）+ CI `mvn test` 兜底。

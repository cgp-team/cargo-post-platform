## 三、后台调度操作

### 3.0 演示主线：346 路司机的一天（三次调度）

> 这一节是答辩主线的"剧本"。数据由 `sql/mysql/demo-line346-orders.sql` 准备，
> 订单都是**待入池**状态；演示时按批次勾选订单 → 归集入池 → 一键调度，一共走三次调
> 度，正好对上"去程 → 返程 → 另一片区"三件事。

**线路背景（全是高德真实公交站位）**

346 路（悠山路 → 较场口）站序：

```
悠山路 → 文峰公社 → 吉祥路口 → 南山路 → 中研所 → 邮电大学 → 黄桷垭 → 崇文路口
      → 上新街 → 龙门浩 → 轨道上新街站 → 小什字小商品 → 临江门 → 较场口（终点站）
```

司机A（渝A·B5204）本职就是跑这条线，每站都停；调度只让他**顺路**取派货，不为了送货专门绕远。

**先说清三件事（答辩口径）**

1. **调度是按"任务时间段"下发的**：调度中心工具栏的「任务窗口」选一个时段（例如 `08:00 ~ 10:00` 早上这一班），
   系统只排这个时间段来得及取送的订单；留空则用"当前时刻起一个班次"。窗口选的时段会写进方案解释里。
2. **默认一条真实线路只跑一辆公交车**：本演示每条真实线路（346 / 347 / 303 / 320 / 220 区间 / 318）各一台车，
   不出现"同一条线好几台车"把画面搞乱的情况。
3. **车已经开过的站，系统不会派它掉头去取货**：系统按线路站序时间轴算出"窗口开始时这台车开到哪一站了"，
   只有**前面还没到的站**才会分给它；取货站全部候选车都已经开过的订单，本批不派，提示"留到下一班次或改派其他线路"。

**第一趟：去程（346 顺路取派 + 跨片区接力）**

先把「任务窗口」调到覆盖当前时段的时段（例如现在 09:10 就选 `08:00 ~ 10:00`），
再勾选这 4 单归集入池后一键调度：

| 订单 | 起点 → 终点 | 说明 |
|---|---|---|
| TP346A | 中研所 → 上新街 | 车到中研所取、到上新街送，同一趟顺路完成 |
| TP346B | 黄桷垭 → 小什字小商品 | 同上，终点站方向顺路送 |
| TP346C | 上新街 → 小什字小商品 | 与 A/B 同车共载，**有先后**：先到站先派 |
| TP346D | 邮电大学 → 重庆工商大学站 | 跨片区，绕不过去 → 346 送到与 320 路的交汇站，**交给 320 的司机续运** |

调度结果的看法：

- **按车辆视角**：司机A 这一台车从始发站出发，一段接一段（中信所取 → 上新街送 → 黄桷垭取 → 小什字送 …），跑完本职线路到终点站较场口。
- **按订单视角**：先看"各车行程链"——每台车的订单按先后串成一条；跨片区的 TP346D 会显示在交汇站"交给 320 的司机（渝A·B5202 · 李伟民）"。
- 地图上**只有真实道路轨迹**：缺路网数据的段直接断开并标注"缺路网轨迹"，不会再出现斜穿城市的直线。

**第二趟：返程（另一次调度）**

司机A 跑到终点站较场口后要返程。这时再单独把 **TP346E（上新街 → 邮电大学）** 归集入池，
点第二次"一键调度"——返程是**独立的一套方案**，调度让他在返程经过上新街时取货、到邮电大学派送。

**第三趟：沙坪坝片区（重庆大学A区）**

再把 **TPCQUA1/2/3** 三单归集入池，出第三套方案：

| 订单 | 起点 → 终点 | 说明 |
|---|---|---|
| TPCQUA1 | 重大A区 → 沙坪坝火车站 | 沙坪坝走廊内接力（220 路区间 623→617/618，由 318 路 414 续到火车站） |
| TPCQUA2 | 重大A区 → 重庆邮电大学站 | 跨片区：沙坪坝走廊 → 自建跨区线 R104 → 重邮，在换乘站交接 |
| TPCQUA3 | 重庆邮电大学站 → 重大A区 | 反向联运 |

> **演示节奏建议：** 先讲 346 主线（第一趟 + 第二趟），再补沙坪坝片区（第三趟）。
> 每次"一键调度"后都点「可视化」看结果；小程序端用司机手机号登录看任务与通知。

**第四趟：用户自己下单的跨线路联运（重邮 → 重庆交通大学）**

这一趟演示"**用户在小程序随便下一单，算法自己解出来怎么走**"——不需要预先准备数据：

1. 小程序用 13800000000 / 123456 登录 → 「寄件」→ 寄件站点选 **邮电大学**、收件站点选 **七公里**
   （七公里就是重庆交通大学南岸校区门口的公交站；也可以在货物备注里写"送重庆交通大学"）
2. 提交后到后台「调度中心」→ 勾选这一单 → 归集入池 → 一键调度
3. 结果：本地线网没有直达线路 → 算法拆成**两段接力**

| 段 | 线路 | 起 → 止 | 说明 |
|---|---|---|---|
| 1 | 347 路（402） | 邮电大学 → 南坪站 | 渝A·B5205（赵德柱）本线路顺路捎带 |
| 2 | 303 路（407） | 南坪站 → 七公里 | 渝A·B5208（303路司机，13800138009）续运 |

4. 可视化「按订单」视角能看到两段分属不同车牌、在**南坪站**交接；司机端对应两位司机各看自己那一段。

> **为什么必然解出这两条线**：候选车辆不是按运力挑的，而是先由算法把订单拆成运输段，
> 再找"起终点都在这条线路上"的线路派车（347 路同时覆盖邮电大学与南坪站；303 路同时覆盖南坪站与七公里）。

## 七、常见问题排查

### Q1: 小程序登录失败（500 错误）

**原因：** 短信验证码渠道未配置

**解决：** 使用"密码登录"模式，不要用短信验证码登录。

### Q2: 一键演示按钮不可用/无反应

**原因：** 订单未入池，或算法服务未启动

**解决：**
1. 确保订单已执行"归集入池"操作
2. 检查算法服务是否运行：docker compose logs algorithm

### Q3: 可视化对话框地图不显示

**原因：** 百度地图 SDK 加载失败（无网络/无 API Key）

**解决：** 系统会自动切换为"坐标示意图"模式（SVG 绘制），功能不受影响。如需真实地图，配置百度地图 API Key。

### Q4: 路线显示为直线而非真实道路

**原因：** 高德地图路径规划 API 不可用

**解决：**
- 系统会自动重试（30 秒冷却期后再次请求）
- 直线段在地图中以虚线显示，右侧面板标注"直线估算"
- 不影响调度方案的正确性，仅影响路线展示精度

### Q5: 司机端看不到任务

**原因：** 登录手机号与调度方案中分配的司机不匹配

**解决：** 查看调度可视化对话框中每条线路的司机手机号，用对应手机号登录。

# 客货邮运营管理平台需求基线

## 业务模块

1. 运营总览：数据大盘首页，展示订单、运力、履约、异常、收入和成本摘要。
2. 车辆监控中心：GIS 实时监控地图、车辆轨迹回放、车辆状态管理。
3. 运力资源管理：车辆注册/审核/档案/到期预警，司机注册/审核/档案/人车绑定，转运中心、乡镇站和村级站点。
4. 班次调度管理：线路班次配置、预约订单池、智能分趟派单、发车核验管理。
5. 订单业务管理：客运订单、货运和生鲜订单、邮快件订单。
6. 财务结算中心：营收统计、运营成本、对账结算。
7. 运维客服中心：异常工单、意见反馈、系统操作日志。
8. 系统基础设置：账号权限、计价规则、公告推送、基础数据字典。
9. 农产品商城（2026-08 增量落地）：管理端商品管理，小程序商城浏览、商品详情、下单与物流溯源；寄件下单、包裹轨迹、司机工作台（班次任务/装车核验/发车签收/收益）均已对接后端真实接口。

## 优先级

括号内为 2026-08-10 的实现现状标注，仅说明进度，不改变需求本身。

### P0：首个可运营版本

- 沿用并验证权限、菜单、字典和日志。（已实现）
- 车辆、司机、站点、线路、班次档案与基本状态。（已实现）
- 客运、货运/生鲜、邮快件三类订单及其状态流转。（已实现）
- 预约订单池、手工派单、模拟智能派单。（已实现，智能派单走 mock 算法与适配层）
- 调度方案审核与下发、发车核验。（已实现）
- 基础 GIS 车辆展示与基础数据大盘。（已实现：班次时间模拟插值实时位置、百度地图 GL 监控页、运营摘要与订单统计图表）

### P1：运营闭环

- 轨迹回放、证照和保险到期预警。（部分启动：车辆位置历史轨迹已落库 `transport_vehicle_location_track` 并服务小程序商品溯源，管理端轨迹回放页面未启动；证照到期字段已在司机档案中预留）
- 工单、反馈、财务统计与对账结算。（反馈已落地：小程序提交 + 管理端回复（transport_feedback）；异常工单、财务统计与对账结算未启动；后端 `service/settlement` 与对应前端目录目前仅占位）
- 真实路线规划算法接入及降级策略。（进行中：适配层与调度闭环已按契约 v0.2.0 打通 mock 算法，待算法组正式镜像交付）

### P2：持续优化

- 自动滚动调度、实时交通数据。
- 多版本算法对比、高级预测和业务预警。

## 关键约束

- 菜单与按钮权限由 system 模块动态管理，不在前端硬编码完整业务路由。
- 前端只能调用业务后端；算法服务只能通过 transport 算法适配层访问。
- 算法服务不持有业务数据库凭据，也不能直接变更订单、车辆或调度状态。
- 所有状态变更需要操作人、时间、前后状态及原因的可审计记录。

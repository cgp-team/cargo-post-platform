# 路线规划算法对接

## 调用边界

```text
管理端前端
  -> 管理端业务后端
    -> transport 模块中的算法适配层
      -> 路线规划算法服务
```

前端不得直接调用算法服务。算法服务不得访问或修改业务数据库；它只处理业务后端生成的快照并返回建议方案。业务后端负责鉴权、幂等、超时、重试、结果校验、人工审核和落库。

## 异步接口

- `POST /api/algorithm/v1/planning-jobs`：提交快照，返回 `jobId`。
- `GET /api/algorithm/v1/planning-jobs/{jobId}`：查询任务状态。
- `GET /api/algorithm/v1/planning-jobs/{jobId}/result`：获取成功、部分成功或无解结果。

完整契约见 `docs/api/algorithm-api.yaml`。时间统一使用带时区的 ISO 8601，例如 `2026-07-16T19:30:00+08:00`。

## 输入预留

任务包含 `requestId`、`snapshotId`、`planningTime`、`rollingWindowMinutes`、`algorithmConfig`。车辆包含车辆 ID、班次 ID、当前位置经纬度、`roadNodeId`、`roadEdgeId`、当前载客量、剩余货运容量、车辆状态和后续站点预计到站时间。订单包含订单 ID、类型、取送节点、件数、重量、体积、最早取货时间、最迟送达时间和优先级。

## 输出预留

结果包含 `jobId`、请求/快照 ID、算法/参数版本、状态、评分、车辆调度方案、订单分配、节点访问顺序、取送动作、预计到达时间、拒绝订单及原因、额外里程、预计乘客延误、预计收入和预计成本。

## 适配层责任

1. 生成全局唯一 `requestId`，保存请求快照哈希，重复请求复用同一业务任务。
2. 设置连接、读取和任务总时限；只对网络错误与服务端可重试错误执行有上限的退避重试。
3. 校验结果中的车辆、班次、订单均属于原快照，容量与时间窗不越界，所有订单只出现一次。
4. 保存算法/参数版本、原始请求和响应摘要，人工审核后才生成正式调度方案。
5. 算法不可用时允许回退手工派单或模拟派单，不自动覆盖已下发方案。

## 待算法组确认

- 坐标系（WGS84/GCJ-02/其他）及转换责任。
- 路网节点和路段数据格式、数据版本与更新方式。
- 时间格式、业务时区与跨日班次规则。
- 单任务最大车辆数、最大订单数、最长计算时间。
- 完整错误码及可重试分类。
- Docker 镜像交付、架构、镜像签名和依赖数据挂载方式。
- 健康检查与就绪检查语义。
- 算法版本、参数版本及兼容规则。
- `requestId` 幂等保留时间与重复提交响应。
- 连接超时、任务超时、轮询频率和重试策略。

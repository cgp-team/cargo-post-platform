## 一、架构总览

```
                    ┌──────────────────────────────────────────┐
                    │           云服务器 (Ubuntu)               │
                    │                                          │
 浏览器/管理端 ───→ │  Nginx :80/:443 (api.qwer2333.com)       │
                    │    │                                     │
                    │    ├─ /api/*  →  :48080 (后端 JAR)       │
                    │    ├─ /ws/*   →  :48080 (WebSocket)      │
                    │    └─ /*      →  /opt/cargo-post-web/    │
                    │                                          │
 Android App ────→  │  Spring Boot :48080 (systemd)            │
                    │    ├─ MySQL :3306 (Docker, 仅本机)       │
                    │    ├─ Redis :6379 (Docker, 仅本机)       │
                    │    └─ Algorithm :18081 (Docker, 仅本机)  │
```

## 二、首次部署（从零开始）

### 2.1 服务器基础环境

```bash
# 1. 系统更新
sudo apt update && sudo apt upgrade -y

# 2. 安装 JDK 21（Eclipse Temurin）
sudo apt install -y wget apt-transport-https gpg
wget -qO - https://packages.adoptium.net/artifactory/api/gpg/key/public | sudo gpg --dearmor -o /usr/share/keyrings/adoptium.gpg
echo "deb [signed-by=/usr/share/keyrings/adoptium.gpg] https://packages.adoptium.net/artifactory/deb $(awk -F= '/^VERSION_CODENAME/{print$2}' /etc/os-release) main" | sudo tee /etc/apt/sources.list.d/adoptium.list
sudo apt update && sudo apt install -y temurin-21-jdk

# 3. 安装 Docker
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker deploy

# 4. 安装 Nginx
sudo apt install -y nginx

# 5. 创建部署用户和目录
sudo useradd -m -s /bin/bash deploy
sudo mkdir -p /opt/cargo-post /opt/cargo-post-web
sudo chown deploy:deploy /opt/cargo-post /opt/cargo-post-web
```

### 2.2 启动基础设施（MySQL + Redis + 算法）

```bash
# 1. 克隆代码
cd /opt
sudo git clone https://github.com/ycg-coder/cargo-post-platform.git cargo-post-platform
sudo chown -R deploy:deploy cargo-post-platform

# 2. 配置环境变量
cd /opt/cargo-post-platform
cp .env.example .env
# 编辑 .env，设置数据库密码、Redis 密码、高德 Key 等
nano .env

# 3. 启动 Docker 容器
cd deploy
docker compose up -d mysql redis algorithm

# 4. 等待 MySQL 就绪，确认能连接
docker compose exec mysql mysql -uroot -p<密码> -e "SELECT 1"
```

### 2.3 初始化数据库

```bash
# 进入 MySQL
docker compose exec mysql mysql -uroot -p<密码>

# 在 MySQL 内执行：
```

```sql
-- 1. 建库
CREATE DATABASE IF NOT EXISTS `cargo_post_dev` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE `cargo_post_dev`;

-- 2. 执行框架基础 SQL（在服务器上用 mysql 命令导入）
```

```bash
# 退出 MySQL 后，按顺序导入 SQL：

# ① 芋道框架基础表（system_users / system_roles / 菜单权限等）
docker compose exec -T mysql mysql -uroot -p<密码> cargo_post_dev < sql/mysql/ruoyi-vue-pro.sql

# ② 业务表（transport_driver / transport_vehicle / 站点 / 线路等）
docker compose exec -T mysql mysql -uroot -p<密码> cargo_post_dev < sql/mysql/transport-schema.sql

# ③ 增量迁移 V001~V027（按版本号顺序）
for f in sql/incremental/V*.sql; do
  echo "Applying $f ..."
  docker compose exec -T mysql mysql -uroot -p<密码> cargo_post_dev < "$f"
done

# ④ 业务菜单
docker compose exec -T mysql mysql -uroot -p<密码> cargo_post_dev < sql/mysql/transport-menu.sql

# ⑤ 初始化账号（管理员 + 司机 + 用户）
docker compose exec -T mysql mysql -uroot -p<密码> cargo_post_dev < sql/cloud/V001__cloud_accounts_init.sql
```

### 2.4 配置后端环境

```bash
# 创建后端环境变量文件（systemd 的 EnvironmentFile）
sudo tee /opt/cargo-post/app.env << 'EOF'
SPRING_PROFILES_ACTIVE=dev
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=cargo_post_dev
DB_USER=root
DB_PASSWORD=<你的数据库密码>
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<你的Redis密码>
REDIS_DATABASE=1
ALGORITHM_BASE_URL=http://127.0.0.1:18081
AMAP_KEY=<高德Web服务Key>
EOF

sudo chmod 600 /opt/cargo-post/app.env
```

### 2.5 部署后端 JAR

```bash
# 方式一：本地构建后上传（无需在服务器装 Maven）
# 在本地开发机：
cd cargo-post-platform
mvn -B -T 1C -pl yudao-server -am clean package -DskipTests
scp yudao-server/target/yudao-server.jar deploy@<服务器IP>:/opt/cargo-post/

# 方式二：服务器上构建（需安装 Maven 3.9+）
cd /opt/cargo-post-platform
mvn -B -T 1C -pl yudao-server -am clean package -DskipTests
cp yudao-server/target/yudao-server.jar /opt/cargo-post/
```

### 2.6 安装 systemd 服务

```bash
# 复制服务文件
sudo cp deploy/cargo-post.service /etc/systemd/system/
sudo cp deploy/cargo-post-watchdog.timer /etc/systemd/system/

# 重载并启动
sudo systemctl daemon-reload
sudo systemctl enable --now cargo-post
sudo systemctl enable --now cargo-post-watchdog.timer

# 查看启动日志
sudo journalctl -u cargo-post -f
# 看到 "Started YudaoServerApplication" 即启动成功
```

### 2.7 配置 Nginx

```bash
# 复制 Nginx 配置
sudo cp deploy/nginx/nginx.conf /etc/nginx/sites-available/cargo-post
sudo ln -sf /etc/nginx/sites-available/cargo-post /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default

# 申请 HTTPS 证书（首次）
sudo certbot --nginx -d api.qwer2333.com

# 检测配置并重载
sudo nginx -t && sudo systemctl reload nginx
```

### 2.8 部署管理端前端

```bash
# 在本地构建前端
cd cargo-post-platform/yudao-ui/yudao-ui-admin-vue3
pnpm install
pnpm build:prod

# 上传到服务器
rsync -avz dist/ deploy@<服务器IP>:/opt/cargo-post-web/
```

## 三、日常部署（代码更新）

### 3.1 自动部署（推荐）

项目已配置 GitHub Actions 自动部署：

- **触发条件**：push 到 `master` 分支
- **执行内容**：自动构建后端 + 前端 + 算法 → 部署 → 健康检查。**数据库不在这条链上**（2026-10-16 起）：
  迁移步骤默认跳过写库，只有仓库变量 `AUTO_DB_MIGRATE=1` 时才重放；常规写库入口是
  `db-migrate-guarded.yml`（见 3.4）
- **查看状态**：GitHub → Actions → "Deploy to dev server"

### 3.2 手动部署后端

```bash
# 1. 拉取最新代码
cd /opt/cargo-post-platform && git pull

# 2. 构建
mvn -B -T 1C -pl yudao-server -am clean package -DskipTests

# 3. 备份旧 JAR
cp /opt/cargo-post/yudao-server.jar /opt/cargo-post/yudao-server.jar.bak

# 4. 部署新 JAR
cp yudao-server/target/yudao-server.jar /opt/cargo-post/

# 5. 重启
sudo systemctl restart cargo-post

# 6. 等待启动（约 30-60 秒）
sleep 30 && curl -s http://127.0.0.1:48080/actuator/health | head -c 200
```

### 3.3 手动部署前端

```bash
cd /opt/cargo-post-platform/yudao-ui/yudao-ui-admin-vue3
git pull
pnpm install && pnpm build:prod
sudo rsync -avz --delete dist/ /opt/cargo-post-web/
```

### 3.4 数据库迁移

常规入口是 GitHub Actions 的 **DB migrate (guarded, manual-only)**，不是命令行循环：

1. 先跑 `mode=check`（默认值）——只读探测，把「执行回流三列 / 钱包三表 / 计价规则菜单」的当前状态和
   6930/6931/6940/6941 各格的主人打在日志里，不写一个字节。
2. 确认无误再跑 `mode=apply`，且 `confirm` 必须原样填 `APPLY`，否则第一步守卫直接终止。
3. apply 只跑幂等白名单（`V028` / `V030` / `V032` + `V035`），末尾「落地核对」步骤按数量判定：
   执行回流列 3/3、钱包表 3/3、列注释无乱码、计价菜单 2/2、6930 仍属货物交接 —— 数不满就红，
   不许把「跑完了」读成「装上了」。

⛔ 以前这一节写的是 `for f in sql/incremental/V*.sql; do … done`，**别再这么跑**：`V*.sql` 里混着
非幂等的一次性脚本，`V026__product_status_flip.sql` 是 `SET status = 1 - status`（跑两次就把上下架翻回去了），
`V029__execution_writeback.sql` 是裸 `ALTER TABLE ADD COLUMN`（第二次必然 `ERROR 1060`，本机 2026-10-12 实测）。
一次性脚本只允许「备份 → 确认目标库 → 单独执行一次 → 记录执行人」那条手工路子，绝不批量循环、绝不进 CI。

真要临时让部署顺带迁移（不推荐），把仓库变量 `AUTO_DB_MIGRATE` 设为 `1` 再 push，跑完清回 `0`。

## 四、账号信息

初始化 SQL 执行后，可使用以下账号登录：

> ⚠ **2026-10-17 实测更正**：云上那张库（`ruoyi-vue-pro`）里 `cargo_admin` 与 `cargoadmin` **两个名字都不存在**
> （guarded 的只读探针现读都是 0），因为 `sql/cloud/V001__cloud_accounts_init.sql` **从没在这张库执行过** ——
> 它不在 guarded 的 apply 白名单里（白名单是 V028、V030–V037、V050–V057）。
> **现在能登进去的是基线自带的 `admin` / `admin123`。**
> 要用 `cargoadmin`，得先决定给它设什么口令、再决定要不要把 V001 收进白名单 —— 那是"在一台公网服务器上
> 开一个默认口令的管理员账号"，不该由脚本替人做主。
> 已核实的相邻约束：登录接口自己校验 `^[a-zA-Z0-9]{4,30}$`，带下划线的 `cargo_admin` 会在鉴权之前就被 400 挡掉
> （这正是 V056 把名字改成纯数字字母的原因）。

## 六、故障排查

### 后端启动失败

```bash
# 查看启动报错
sudo journalctl -u cargo-post --no-pager -n 100

# 常见原因：
# 1. 数据库连不上 → 检查 Docker 容器是否运行：docker compose ps
# 2. 端口被占用 → ss -tlnp | grep 48080
# 3. JDK 版本不对 → java -version（必须是 21）
```

### App 登录报"账号不存在"

```bash
# 检查 member_user 表是否有对应手机号
docker compose exec mysql mysql -uroot -p cargo_post_dev \
  -e "SELECT id, mobile, nickname, status FROM member_user WHERE mobile='13900001003'"

# 如果为空，重新执行账号初始化 SQL
docker compose exec -T mysql mysql -uroot -p cargo_post_dev < sql/cloud/V001__cloud_accounts_init.sql
```

### 司机登录后显示"不是司机"

```bash
# 检查 transport_driver 表是否有匹配手机号的记录
docker compose exec mysql mysql -uroot -p cargo_post_dev \
  -e "SELECT id, name, mobile, status FROM transport_driver WHERE mobile='13900001003'"

# 后端匹配逻辑：member_user.mobile → transport_driver.mobile
# 两个表的 mobile 必须完全一致（含空格都会导致匹配失败）
```

### 管理端页面空白

```bash
# 检查前端文件是否到位
ls -la /opt/cargo-post-web/index.html
ls -la /opt/cargo-post-web/assets/

# 检查 Nginx 配置
sudo nginx -t
cat /etc/nginx/sites-available/cargo-post

# 检查后端 API 是否通
curl -s http://127.0.0.1:48080/admin-api/system/auth/login -X POST \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | head -c 300
```

## 七、安全清单

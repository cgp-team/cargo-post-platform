## 摘要

针对农村「客货邮」融合场景下公交骨架带货的插入调度问题，本文在**不使用伪造坐标的前提下**构建训练数据并训练插入位置排序模型。线路与站点取自 OpenStreetMap 重庆区域 `route=bus` 共 **454** 条真实公交线路、**9,071** 个真实站点；道路距离全部由本地 OSM 路网（约 223 万节点）最短路计算，**禁止直线距离替代**。订单在真实站点坐标上按客货邮产品分布随机生成，并对类型配比、批量、离群件、绕行预算、场站、插单顺序与容量等非真实维度做高方差扰动，以降低过拟合、提升鲁棒性。标签采用「产品优先级 + 一步前瞻堵死惩罚」的混合排序目标。在一次生成 **3,000** 场景（**17,815** 个插单决策组 / **237,127** 候选行 / **471,543** 次真实算路、**0** 错误）的基础上，按场景前缀切片形成学习曲线，并用 LightGBM 小网格自动调参。结果表明：随数据规模增大，按线路留出验证的 Top-1 由 0.60 升至 **0.75**，Top-3 由 0.89 升至 **0.95**，NDCG@5 由 0.85 升至 **0.90**；2,000～3,000 场景区间指标增幅已收敛于 0.02 以内，可认为在当前特征与标签口径下接近饱和。模型已接入调度搜索的候选重排（`use_branch_ranker=auto`），多种子真实线路 A/B 显示在无大幅劣化的前提下降低目标里程约 4%～14%。其业务价值在于：在客货邮「公交骨架带货」派单中自动优选插单站位，降低绕行与里程、稳定班点，并以「只重排、不砍单」约束保证服务安全。

**关键词：** 农村客货邮；公交骨架；插入排序；LambdaRank；OSM；真实道路；学习曲线；鲁棒性

## 1 引言

### 1.1 背景与问题

农村客货邮融合要求在既定公交班线上兼顾客运与快件/农产物流：骨架站必须按序停靠（每站必停），货件可在站序间隙插入上下客点。插入位置的选择直接影响乘客影响（pax impact）、绕行（detour）与里程/时长，是调度搜索中最热的决策点之一。启发式评分在候选池较大时排序不稳定，难以兼顾产品优先级与全局里程。

### 1.2 目标

1. 仅使用**真实公交线路、真实站点、真实道路里程**构建训练数据（订单坐标亦落在真实站上）；
2. 覆盖重庆主要区域与客货邮典型单型，保证分布鲁棒；
3. 训练可解释、可门禁的插入排序模型，辅助贪心种子与搜索阶段重排；
4. 给出**可复现的学习曲线**与调参结论，支撑项目报告与后续生产订单接入。

### 1.3 贡献摘要

- 修复 OSM PBF Relation 解析，抽取全网 `route=bus` 站序作骨架；
- 训练/推理共用 26 维特征，消除 train/serve 口径漂移；
- 混合标签（产品字典序 + 一步前瞻堵死惩罚）在安全与里程收益间取得平衡；
- 一次生成 + 前缀切片的规模化训练与自动调参流水线，并给出稳定性判据。

## 2 数据

### 2.1 真实地理与线网数据

| 数据 | 来源 | 规模 | 用途 |
|------|------|------|------|
| 公交线路与站序 | OSM `route=bus` Relation | **454** 条（≥5 站） | 骨架（每站必停 PASS） |
| 站点坐标/站名 | OSM bus_stop / platform 等 | **9,071**（主城/万州/合川/大足/江津/綦江等） | 订单 OD、矩阵 |
| 道路图 | 重庆 OSM PBF | ~**223 万**节点 | **唯一**距离来源 |
| 线路抽取结果 | `osm_routes_full.json` | 约 7,200+ 关系解析后过滤 | 训练骨架 |

**不变式：** 线路、站点、道路里程全部真实；禁止 `直线 × 1.3` 顶替道路距离（特征与 OD 矩阵均强制）。

### 2.2 订单生成（真实坐标上的产品分布 + 高方差）

订单不是生产库历史单，而是**落在真实站点坐标上的客货邮产品分布样本**，并对一切非真实维度做随机化：

| 维度 | 随机策略 |
|------|----------|
| 单量 | 2～14（含极稀、极挤场景） |
| 类型 | 客运 / 联运出山 / 快递进村 / 返程揽收；每场景重抽权重；8% 单类型难例 |
| 离群件 | 15% 大件/超重/高价 |
| 客运 OD | 骨架站贴站上下；20% 逆向制造顺序压力 |
| 货运 OD | 站池随机（联运/出山/进村/揽收） |
| 骨架窗口 | 真实站序连续 4～16 站；15% 整线 |
| 空间范围 | OD 池半径 5/8/12/18/25 km 随机 |
| 场站 DEPOT | 骨架前 4 站随机 |
| 插单顺序 | 订单序列 shuffle |
| 容量/载荷 | 乘客 8～28、货舱 12～48；初始载荷 0～33% |
| 绕行预算 | 1.5 / 2 / 2.5 / 3 / 4 / 5 km |
| 候选池 | candidate_size ∈ {16,24,32,48} |
| 时长 | 真实里程不变，ETA × 0.75～1.35 抖动 |

### 2.3 训练样本结构（group）

每个 **group** 对应「一张单在同一时刻、同一路线状态下的插入候选池」：

- 候选：不同上/下客下标的可行插入位；
- 特征：26 维/候选（里程、绕行、乘客影响、位置占比、未放单量、剩余 gap 等）；
- 标签：组内排序分 3/2/1/0（见 §3.2）。

一次生成 3,000 场景后得到 **17,815 groups / 237,127 rows**。

## 3 方法

### 3.1 问题形式化

给定真实公交骨架站序 $S=(s_1,\ldots,s_m)$（必停）与当前已插入集合，对新任务 $t$ 在合法 gap 内选择插入位 $(i,j)$，优化产品目标：

1. 乘客影响（pax impact）最小；
2. 货绕行（cargo detour）受预算约束且尽量小；
3. 里程与 时长 尽量小。

模型学习候选之间的**相对序**，供排序/重排使用，而非直接回归全局费用。

### 3.2 标签：混合全局对齐

对候选 $c$ 与一步前瞻堵死数 $b(c)\in\{0,1,2\}$（试插入后抽查剩余任务是否变为 0 候选）：

$$
\mathrm{key}(c)=\Big(\;\mathrm{round}(\mathrm{pax},3),\;\mathrm{round}(\mathrm{detour},1)+10\cdot b(c),\;\mathrm{round}(\Delta \mathrm{km},2),\;\mathrm{round}(\Delta t,2)\;\Big)
$$

按 $\mathrm{key}$ 字典序排序后映射为 3/2/1/0。设计要点：

- **detour 粗粒度（0.1 km）**：避免厘米级噪声压过里程；
- **$b(c)$ 重罚**：防止「局部最优插入」堵死后续任务；
- **仅用于标签**：$b$ 不进特征，保证 train/serve 同分布（实践证明 $b$ 进特征会导致偏斜甚至空解）。

### 3.3 特征（26 维，训练=推理）

里程/绕行/乘客影响/启发式分、任务类型 one-hot、件重体价、插入相对位置、事件数、绕行预算占用、**真实道路 OD 里程**与直线对比、**未放单量 n_unplaced**、**剩余 gap 数 n_gaps** 等。道路特征缺失时**抛错**而非回落直线。

### 3.4 模型与门禁

LightGBM **LambdaRank**。安全门：`can_rank = (top3 ≥ 0.80)`，`can_prune = (top3 ≥ 0.99)`（只重排、不硬砍）。推理 Quality Fuse：归一化 ML 分与启发式分加权（blend=0.75）。

### 3.5 求解器中的使用方式

| 阶段 | 行为 |
|------|------|
| 贪心种子 | 最难任务优先 + 产品优先级选位（与标签同口径） |
| 搜索插入 | `generate_insertion_candidates` 后 ML 重排（`use_branch_ranker=auto`） |
| 深度 | 默认 ACO `max_iterations=8`（实测更深目标变差，收尾交 ALNS） |

### 3.6 验证协议

- **按线路留出（route_holdout）** 20% 验证线路，禁止同线泄漏；
- 学习曲线：**一次生成 3,000 场景 → 按场景前缀切片**（400⊂600⊂…⊂3000）；
- 自动调参：`num_leaves ∈ {21,31,41,63}` × 学习率/叶节点最小样本/ L2 的小网格，按 `top3 + 0.25×NDCG@5` 选优。

## 5 结果与分析

### 5.1 学习曲线（route_holdout）

| 场景前缀 | groups | rows | Top-1 | Top-3 | NDCG@5 | can_rank | 调参（最优） |
|----------|--------|------|-------|-------|--------|----------|--------------|
| 400 | 2,399 | 32,303 | 0.598 | 0.892 | 0.848 | ✓ | — |
| 800 | 4,738 | 63,386 | 0.652 | 0.906 | 0.876 | ✓ | leaves=21, lr=0.05 |
| 1,000 | 5,996 | 79,969 | 0.647 | 0.891 | 0.865 | ✓ | leaves=21 |
| 1,200 | 7,236 | 96,519 | 0.664 | 0.914 | 0.879 | ✓ | leaves=21 |
| 1,500 | 8,925 | 119,768 | 0.699 | 0.922 | 0.884 | ✓ | leaves=21 |
| 2,000 | 11,893 | 158,793 | 0.724 | 0.929 | 0.894 | ✓ | leaves=21 |
| 2,500 | 14,820 | 197,706 | 0.746 | 0.937 | 0.900 | ✓ | leaves=21 |
| **3,000** | **17,815** | **237,127** | **0.752** | **0.946** | **0.904** | ✓ | leaves=21 |

**趋势分析**

1. **规模收益明确**：Top-1 相对 400 场景提升约 **15.4 个百分点**；Top-3 进入 0.93～0.95 稳定带。
2. **末段趋稳**：2,500→3,000 的 ΔTop-3≈0.009、ΔNDCG≈0.004，均 &lt; 0.02；2,000 起可认为接近饱和。
3. **1,000 档微降**：前缀切片下样本构成仍有随机波动，说明单档 ±0.02 内抖动属正常，不宜过早宣称稳定（故稳定性要求连续 3 档）。
4. **调参稳定落在浅树**（`num_leaves=21`），与「防过拟合、特征已较干净」一致；更深树（41/63）无持续优势。

### 5.2 下游多种子真实线路 A/B（离线代理指标）

在 5 条真实线 × 5 种子、22 单大候选池设定下（里程为欧氏口径 degree，**比值可比**）：

| 指标 | 历史干净区间（多轮） |
|------|----------------------|
| force 更优场次 | 3～4 / 5 |
| 里程比 force/off 均值 | **0.86～0.96** |
| 里程比中位数 | 0.91～0.97 |
| 大幅劣化 | **无**（最差约 1.02） |

结论与「模型只重排、不硬砍」的安全设计一致：**收益为正且有上界风险可控**。

### 5.3 消融与工程结论（支撑报告书）

| 结论 | 依据 |
|------|------|
| 直线距离灌水 + 同线泄漏会虚高指标 | 修正后 Top-3 从虚高 ~0.94 诚实降至可复现 0.85～0.95 区间 |
| 搜索深度非越大越好 | 纯 ACO 2 层优于 8/20 层；默认 `max_iterations=8` |
| blocked 不可进特征 | 进特征导致 train/serve 偏斜与空解；仅进标签 |
| 2-step 前瞻标签线上更差 | 离线略升、A/B 变差，维持 1-step |
| 高方差订单生成必要 | 固定窄分布易过拟合单一场景形态 |

## 6 讨论

### 6.1 「真实」边界

| 真实 | 合成（真实坐标上的分布） |
|------|---------------------------|
| 线路、站序、站名、坐标 | 订单 OD 组合与到达批量 |
| 道路里程（路网最短路） | 件重体价、经济价值 |
| 骨架每站必停约束 | 类型配比、插单顺序、容量等业务参数 |

接入生产历史订单时，仅需替换订单生成模块，特征/标签口径保持不变。

### 6.2 局限

1. 订单为产品分布合成，非生产单；时间窗/实时路况未建模；
2. A/B 里程单位为欧氏 degree，需在生产口径下用公里复验；
3. `can_prune`（top3≥0.99）尚未达标，故只做重排；
4. 站点吸附导致约 0.6% 零长 OD，已计入统计。

### 6.3 后续工作

1. 生产真实订单微调与校准；
2. 公里口径 + 在线 SLA 下的 A/B；
3. 特征压缩与推理延迟预算（当前 `predict` 为 O(n)）。

## 7 结论

本文在重庆全网真实公交线路/站点/道路数据上，以高方差客货邮订单生成与混合标签训练插入排序模型，并通过「一次生成 + 前缀切片」给出完整学习曲线。最优配置下（LightGBM LambdaRank，`num_leaves=21`，`learning_rate=0.05`），3,000 场景 / 23.7 万候选行时 route_holdout **Top-3=0.946、NDCG@5=0.904**，且 2,000 场景后增幅进入 0.02 稳定带。模型在下游插入重排中取得稳定正收益且无大幅劣化，满足「先排序、不硬砍」的生产安全约束，可直接纳入项目报告书作为算法侧训练与验收依据。

**应用价值见第 8 章：** 该模型用于客货邮「公交骨架带货」场景下的插单站位优选，直接服务于降本（里程/绕行）、稳班（乘客影响优先）与服务安全（只重排不砍单），并为后续接入生产真实订单留出稳定接口。

## 8 模型用途与应用价值

### 8.1 解决什么业务问题

农村客货邮融合要求在**既定公交班线**上兼顾客运与快件/农产物流：骨架站必须按序停靠，货件在站序**间隙**选择上下客点。每一次「新单插入哪一站」都是高频决策——插错站会带来：

- 绕行过多、里程与油耗上升；
- 打乱乘客上下客节奏（误点、体验变差）；
- 前期插得过死，后续单「插不进去」（可行位被堵死）。

本模型不替代整段路径规划/调度求解器，而是专门优化 **「插单站位排序」** 这一最热子问题。

### 8.2 在系统中的位置（有什么用）

```text
运营下单（客运 / 快递进村 / 农产出山 / 返程揽收）
        ↓
公交骨架（真实线路站序，每站必停）
        ↓
生成可行插入位（骨架 gap 内的上/下客配对）
        ↓
★ 插入排序模型（本文）对候选位打分排序
        ↓
贪心种子落位 + 搜索阶段重排（use_branch_ranker=auto）
        ↓
输出执行计划（少绕行、少误点、少空跑、不砍单）
```

### 8.3 对项目/运营的直接价值

| 价值维度 | 说明 | 依据 |
|----------|------|------|
| **降本** | 优选插单位，降低总里程与绕行 | 多种子真实线路 A/B：里程比 force/off 均值约 0.86～0.96（省约 4%～14%） |
| **稳班** | 乘客影响（pax）为标签最高优先级 | 混合标签第一字典序为 passenger_impact |
| **服务安全** | 「只重排、不硬砍」 | `can_prune` 未达标前禁止丢弃候选；A/B 未分配恒为 0 |
| **抗波动** | 高方差合成订单训练，避免背死单一场景 | 类型/容量/窗口/离群件/插序全面随机 |
| **可演进** | 有生产历史单后可直接微调，口径不变 | 特征/标签接口稳定（26 维 + 产品优先级） |
| **可验收** | 学习曲线、调参、A/B 齐全，便于写入项目书 | 本文 §5 与附录 A |

### 8.4 使用与门禁

| 项 | 行为 |
|----|------|
| 开关 | `use_branch_ranker = auto \| force \| off`（生产建议 **auto**） |
| 启用条件 | 验证 Top-3 ≥ 0.80 才 `can_rank`；否则回退启发式 |
| 行为 | Quality Fuse 重排候选序；**永不因模型丢弃候选** |
| 风险上界 | 多种子实验最差约 1.02（无大幅劣化） |

### 8.5 一句话总结

**本模型让客货邮调度在「公交骨架上插单」这一步更聪明：少绕行、少误点、少空跑，且不牺牲「单必须送达」的服务底线。**
